SimonBot

Simon's community bot for Discord, running on your own machine.

Get started View on GitHub

SimonBot looks after a Discord server for a streamer. It welcomes people, hands out roles, keeps levels and points for everybody who talks in Discord, runs giveaways and questions, and posts when the stream goes live. Its look is taken from the bot's avatar (Pixel Simon holding a pixel heart, in leaf, mint, grape and plum).

Everything runs without a browser open. The server owns every connection; the dashboard is only where you set it up, and closing it changes nothing.

Every dashboard is a replica. None of them hold authority, so opening or closing one changes nothing about what the bot is doing.

What SimonBot does

Module What it does
Welcome & goodbye A drawn card and a message when somebody joins, leaves, boosts or is banned
Levels & XP XP for talking in your Discord server, one level per person
Points A score apart from XP, earned by talking and by coming to streams in a row, with a board of its own
Giveaways Open a giveaway; people enter from Discord, with a button or /sorteo
Go live A Discord post for each Twitch or YouTube channel on your watch list when it goes live, and a DM to whoever asked
Role menus Reaction roles and button menus people press to take a role
Questions & requests Questions asked in Discord collected for the stream, game requests voted on in Discord
Polls Not yet: a poll maker built on Discord's own polls is coming. The Polls screen is a placeholder
Discord pages Rules, information and links as tidy channel posts, built from blocks
Voice The bot joins a voice call and shows who is in it
Mod log Bans and timeouts posted to a Discord channel you choose

Slash commands. Typing / in your server lists them, in Spanish first and in English on an English Discord. Each answers the same way its button or ! word does.

Command What it does
/perfil Your level, points and streak, as a card
/rango Your level and place
/top Who leads the levels
/puntos How many points you have, shown only to you
/sorteo Enter the open giveaway
/avisame A DM when the stream starts, with a link to where you watch: Twitch or YouTube
/pregunta A question for the stream

The bot's home shows whether SimonBot is online and which server it is looking after, what it will do when you go live, every module with its state, and two buttons: one gives the bot account Pixel Simon's face (no trip to the Developer Portal), the other registers the slash commands again.

Going live is read from the watch list: the Twitch and YouTube channels you add on the Go live screen, each with its own post. Twitch is asked every minute and YouTube every two and a half. Channels marked with the star are yours: while one of them is live, the stream is on, and the DMs and points for coming follow it. Nobody signs in to Twitch or YouTube for this; it needs only the keys on the Connections screen.

Versions. SimonBot numbers its own versions, from 0.0.1. What each version changed is in CHANGELOG.md, and how the numbers move is explained at its top. The running server reports its version at /api/health, and the app shows it under Settings → About.

Privacy. What it keeps about you and your viewers, where, and what reaches which service is in PRIVACY.md. Nothing is ever sent to the people who make it.

Getting started

About half an hour from nothing to SimonBot answering in your server. The app also walks you through all of this itself, on its home screen and in Guides, in English and Spanish — this is the same path, written down.

What you need

  • A computer to run it on, on while the bot should be. Windows, macOS or Linux; a spare PC or an old Android phone on your network works too.
  • Node.js 22 or newer. Take the LTS installer and keep its defaults. To check, open a terminal and run node -v.
  • A Discord server you manage, for the bot.
  • Keys for the channels you stream on, for go-live posts: a Twitch app, and a YouTube API key if you use YouTube. Nobody signs in to either.

1. Download it

On GitHub, press Code → Download ZIP and unzip it somewhere that stays put, like Documents\SimonBot. Or, with git, copy the address under Code and run git clone with it.

2. Install it

Open a terminal in that folder. On Windows: open the folder, right-click an empty space, and choose Open in Terminal. Then:

npm install

It downloads what the app needs. A few minutes, once.

3. Start it

npm run serve

The first time it builds the app, then starts it. When it says listening on http://0.0.0.0:8081, it's running. Leave that window open — it is the bot. Closing it stops everything; closing the browser doesn't.

Every time after that, npm start is enough.

4. Open it

Go to http://localhost:8081 in your browser. SimonBot's home screen says whether the bot is connected, and Guides lists the setup steps still to do, each with a button to where it's done.

5. Connect SimonBot to Discord

  1. At discord.com/developers/applications, press New Application and name it (SimonBot, or what your bot should be called).
  2. Under Bot, turn on Server Members Intent and Message Content Intent (Privileged Gateway Intents). The bot won't connect without them.
  3. Copy the Client ID (OAuth2), the bot token (Bot → Reset Token, shown once) and the client secret (OAuth2 → Reset Secret).
  4. Under OAuth2 → Redirects, add the dashboard's address, http://localhost:8081/ (the one the Connections screen shows). Signing in with Discord comes back there.
  5. On the Connections screen, paste the three, press the Discord login, then pick your server and the channel the bot talks in.
  6. In Discord, Server Settings → Roles: drag the bot's role above every role it should hand out (levels, role menus).
  7. Back on SimonBot's home, press Use SimonBot's face to give the bot its avatar, and Register / commands so / lists its commands.

6. Connect where you stream

Nobody signs in to Twitch or YouTube: SimonBot only reads their public live status, with the keys below. On the Connections screen:

  • Twitch needs an app of your own, made once:
    1. Turn on two-factor authentication on your Twitch account (twitch.tv → Settings → Security and Privacy). Twitch won't let you make an app without it.
    2. At dev.twitch.tv/console/apps, press Register Your Application. Any name; OAuth Redirect URLs: http://localhost (Twitch asks for one; nothing signs in with it); category: Application Integration; client type: Confidential.
    3. Press Manage, copy the Client ID, press New Secret and copy the Client Secret. Paste both on the Connections screen.
  • YouTube needs an API key from Google Cloud: enable the YouTube Data API v3, then Credentials → Create credentials → API key. Paste it on the Connections screen.

Guides → Start here has a click-by-click walkthrough for each.

Then add the channels to watch on the Go live screen. Mark your own with the star.

7. Make it yours

  • Welcome & Goodbye: the card, the message and the buttons under it.
  • Role menus: the roles people take for themselves.
  • Go live: the channels to watch, each with its own post, and the DMs.
  • Levels, Points, Giveaways, Questions, Game requests and Moderators (the mod log): each has its own screen. Polls is a placeholder for now.

8. Before anyone else can reach it

On your home network nothing more is needed. If the app can be reached from anywhere else — a public address in front of it, say — switch sign-in on first (Settings → Sign-in): from then on only you and the moderators of your Discord server can open the dashboard. Every address you sign in from must be added to your Discord app's OAuth2 Redirects, as in step 4.

You sign in with Discord. You are the owner if you own the server, or if you are the account named under Settings → Sign-in ("Your Discord account"). Moderators sign in with their own Discord account, as long as they are in your server and have the moderator role you choose, or any role that can time out or manage messages. The Moderators screen shows who's in, what they did, and lets you turn anybody away.

If something goes wrong

  • "Port 8081 is already in use": the app is already running, in another window. Use that one, or close it first.
  • '&&' is not a valid statement separator (Windows PowerShell 5.1): run the commands on separate lines, or join them with ;.
  • Discord says the redirect is invalid: the address in the Discord app's OAuth2 Redirects must be exactly the one you opened, http://localhost:8081/ — slash included.
  • A phone or another PC can't open it: allow Node.js through the Windows firewall on private networks (Windows asks the first time).
  • Anything else: Guides has a "when it doesn't work" list for every platform.

Keys in a file, if you prefer

Everything above goes in through the app, and the server keeps it. To set the port, the address it listens on, or platform keys in a file instead, copy .env.example to .env and fill in what you need; anything left blank is ignored.

Closing the dashboard

Start the server, set it up, then close every browser tab. Welcomes, roles, levels, giveaways, go-live posts and slash commands all keep working.

Check on it from anywhere:

curl localhost:8081/api/health

Using it from another device

The server holds every credential, connection and setting, so any device that can reach it gets the same fully set-up app.

On the host machine, build once and serve everything from a single port:

npm run serve

On any other device — laptop, phone, tablet — open:

http://<host-machine-ip>:8081

A few things worth knowing:

  • Set the keys up once, on the host. They live on the server, so every other device uses them. Secrets (the bot token, the client secrets and the YouTube key) can only be typed on the host machine itself.
  • Prefer npm run serve over npm run dev for this. In dev the UI is on port 5173 and the API on 8081 — two different addresses, which means two separate localStorage buckets and a second Discord redirect URL to register.
  • Only per-device preferences stay on the device: language and colours.
  • Firewall: Windows will likely prompt the first time something connects from another machine. Allow it on private networks.
  • Switch sign-in on before it can be reached from outside your home (Settings → Sign-in). Until then there is no authentication: anybody who can reach the port has all of it. Set HOST=127.0.0.1 to restrict it to the host machine only.
  • Signing in with Discord comes back to the address it was opened at, so every address you or your moderators use has to be added to your Discord app's OAuth2 Redirects (discord.com/developers/applications → your app → OAuth2).

To point a dev-mode UI at a server on another machine, append ?server=ws://<host-ip>:8081 to the URL.

Layout

server/           headless service — the whole application
  core/           event bus, atomic store, queues, logging
  engine/         welcomes, roles, go-live, giveaways, questions, points…
  platforms/      twitch, youtube, discord, discord-voice
  leveling/       XP and levels
  api/            REST + WebSocket hub, sign-in
  scripts/smoke.js  end-to-end test, no network needed — runs scripts/smoke/,
                    a file per part of the app, on one engine, in order

shared/           code both sides run: wire protocol, guides, card styles

web/              the dashboard
  App.tsx         shell and navigation
  components/     screens (views/) and their parts
  hooks/          thin client over the one server socket

See docs/ARCHITECTURE.md for how the server is put together.

Testing

npm --prefix server run test

Boots the engine with stub platforms, pushes synthetic chat and events through the bus, and asserts on the results. No network and no browser.

Developing

npm run dev

Runs the server on :8081 and the UI on :5173, reloading as you edit. It has no updater; keep a development copy up to date with git.

Where it came from

SimonBot started as a copy of SimonSays, Simon's stream app, with everything about running and decorating the stream — overlays, alerts, OBS, the docks, commands and actions, Spotify — taken out. What is left is the server that SimonSays V3 made headless, and the community features that live in Discord.
